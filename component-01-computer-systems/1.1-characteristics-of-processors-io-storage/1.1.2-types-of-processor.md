# 1.1.2 Types of Processor

> **Component:** 01 — Computer Systems | **Section:** 1.1 | **Sub-section:** 1.1.2

## What you need to know

Not all processors are the same. This topic covers different **processor architectures** (CISC vs RISC), the use of **GPUs** for parallel processing tasks, and the concept of **multi-core** and **parallel processors**. You need to be able to compare these architectures and explain when each is appropriate.

## Key terms

| Term | Definition |
|------|-----------|
| **CISC** | Complex Instruction Set Computer — architecture with many complex instructions, some taking multiple clock cycles |
| **RISC** | Reduced Instruction Set Computer — architecture with a small set of simple instructions, each executing in one clock cycle |
| **GPU** | Graphics Processing Unit — processor with thousands of smaller cores optimised for parallel tasks |
| **Multi-core** | A single chip containing two or more independent processor cores |
| **Parallel processing** | Multiple processors executing instructions simultaneously |
| **Co-processor** | A secondary processor that handles specialist tasks (e.g. floating-point calculations, graphics) to offload the main CPU |
| **Pipeline** | Overlapping execution of instructions (see 1.1.1) |

## Core notes

### CISC vs RISC

| Feature | CISC | RISC |
|---------|------|------|
| **Instruction set size** | Large — hundreds of instructions | Small — typically under 100 |
| **Instruction complexity** | Complex; some take many cycles | Simple; each executes in one cycle |
| **Registers** | Fewer | Many general-purpose registers |
| **Memory access** | Many instructions can access memory | Only LOAD/STORE instructions access memory |
| **Pipelining** | Harder (variable instruction length) | Easier (uniform instruction length) |
| **Code density** | Fewer instructions needed per task | More instructions needed, but simpler |
| **Examples** | x86 (Intel/AMD) | ARM (smartphones, tablets) |

**CISC advantage:** Compilers can use powerful instructions to reduce code size.  
**RISC advantage:** Simpler instructions allow efficient pipelining and easier hardware design.

### GPUs

- A GPU contains thousands of smaller, simpler cores compared to a CPU's few powerful cores
- Ideal for tasks that can be broken into many simultaneous operations (e.g. rendering pixels, machine learning matrix calculations, scientific simulation)
- **GPGPU** (General-Purpose GPU computing) — using GPUs for non-graphics tasks
- GPUs are used in: 3D rendering, cryptocurrency mining, AI/ML training, scientific computing

### Multi-core processors

- Multiple complete processor cores on a single chip
- Each core can execute its own thread independently
- Operating system schedules threads across cores for true parallelism
- More cores help with multi-threaded applications (e.g. video editing, web servers)
- A single-threaded task does not automatically benefit from extra cores

## Worked examples

### Example — RISC instruction sequence

CISC equivalent (one instruction): `MULT A, B` — multiply A by B directly in memory  
RISC equivalent (three instructions):
```
LOAD R1, A      // load A into register R1
LOAD R2, B      // load B into register R2
MUL R3, R1, R2  // multiply R1 and R2, store in R3
STORE R3, C     // store result
```
RISC uses more instructions but each is simpler and faster per clock cycle.

## Common mistakes

- ❌ **Mistake:** Saying RISC processors are always faster than CISC.  
  ✅ **Correction:** RISC pipelines more efficiently, but modern CISC processors (like x86) translate complex instructions into RISC-like micro-operations internally — the comparison is not straightforward in practice.

- ❌ **Mistake:** Saying a GPU can replace a CPU.  
  ✅ **Correction:** GPUs are optimised for massively parallel tasks; CPUs handle sequential, complex decision-making better. They complement each other.

## Quick-check questions

1. What does RISC stand for?
2. Give two differences between CISC and RISC.
3. Why are GPUs well suited to machine learning tasks?
4. Does adding more cores always improve performance? Explain.

<details>
<summary>Outline answers</summary>

1. Reduced Instruction Set Computer.
2. Any two: RISC has fewer/simpler instructions; RISC executes each instruction in one clock cycle; RISC has more registers; RISC only accesses memory via LOAD/STORE; CISC has a larger instruction set; etc.
3. ML involves many parallel matrix calculations; GPUs have thousands of cores and can perform these calculations simultaneously.
4. No — only multi-threaded software benefits. Single-threaded programs cannot automatically split across cores.

</details>
