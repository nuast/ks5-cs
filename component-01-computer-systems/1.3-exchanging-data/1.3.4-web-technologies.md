# 1.3.4 Web Technologies

> **Component:** 01 — Computer Systems | **Section:** 1.3 | **Sub-section:** 1.3.4

---

## What you need to know

The web is built on a set of technologies that allow content to be created, served, and displayed. You need to understand how web pages are structured (HTML), styled (CSS), made dynamic (JavaScript), and how servers handle requests. You also need to know how search engines work and the difference between client-side and server-side processing.

## Key terms

| Term | Definition |
|------|-----------|
| **HTML** | HyperText Markup Language — defines the structure and content of a web page |
| **CSS** | Cascading Style Sheets — defines the appearance/style of HTML elements |
| **JavaScript** | A high-level, client-side scripting language that makes web pages interactive |
| **DOM** | Document Object Model — a tree representation of the HTML structure that JavaScript can manipulate |
| **Client-side** | Processing that happens in the user's browser |
| **Server-side** | Processing that happens on the web server before the page is sent to the client |
| **PHP** | A server-side scripting language used to generate dynamic web content |
| **Web crawler** | An automated program that traverses the web, downloading pages for a search engine to index |
| **Search index** | A database of words and the pages they appear on, used to answer search queries |
| **PageRank** | Google's algorithm for ranking pages based on the number and quality of links pointing to them |
| **Cookie** | A small file stored on the client's machine by a web server to maintain state |
| **Session** | Server-side storage of user state data; identified by a session ID stored in a cookie |

## Core notes

### HTML

Defines **structure** and **content** using tags:

```html
<!DOCTYPE html>
<html>
  <head>
    <title>Page Title</title>
    <link rel="stylesheet" href="style.css">
  </head>
  <body>
    <h1>Main Heading</h1>
    <p>A paragraph of text.</p>
    <a href="https://example.com">A link</a>
  </body>
</html>
```

Semantic tags give meaning: `<header>`, `<nav>`, `<main>`, `<footer>`, `<article>`.

### CSS

Defines **style** separately from structure:

```css
body {
    font-family: Arial, sans-serif;
    background-color: #f0f0f0;
}
h1 {
    color: navy;
    font-size: 2em;
}
```

Separation of concerns: HTML = what the content is; CSS = how it looks.

### JavaScript

Makes pages **interactive** on the client side:

```javascript
// Change heading text when button is clicked
document.getElementById("myButton").addEventListener("click", function() {
    document.getElementById("heading").textContent = "Clicked!";
});
```

- Runs in the browser (client-side)
- Can manipulate the DOM (the structure of the page) dynamically
- No round trip to server needed for simple interactions

### Client-side vs server-side processing

| Feature | Client-side | Server-side |
|---------|------------|------------|
| **Where it runs** | User's browser | Web server |
| **Language examples** | HTML, CSS, JavaScript | PHP, Python, Node.js, Ruby |
| **Speed (for user)** | Fast (no network round trip) | Depends on server and network |
| **Security** | Source code visible to user | Source code hidden from user |
| **Use case** | Form validation, animations, interactive UI | Database queries, authentication, generating personalised pages |

### How search engines work

1. **Crawling** — web crawlers (spiders/bots) follow links across the web, downloading pages
2. **Indexing** — the content is analysed and added to a search index (a massive database of words → pages)
3. **Ranking** — when a user searches, the engine ranks matching pages using algorithms including:
   - **Relevance** (does the page contain the search terms?)
   - **PageRank** (how many quality pages link to this page?)

**PageRank:** A page linked to by many high-quality pages gets a higher rank. This was Google's original key innovation.

### Cookies and sessions

**Cookies:** Small text files stored on the client's machine. Used to:
- Remember login state
- Store preferences (e.g. theme, language)
- Track user behaviour (analytics/advertising)

**Sessions:** State stored on the server (e.g. shopping cart, logged-in user data). A session ID is sent to the client as a cookie. Each request includes the session ID so the server knows which user's data to retrieve.

**Web security basics:**
- **HTTPS** — encrypts all data between browser and server (see 1.3.1, 1.3.3)
- **SQL injection** — inserting malicious SQL into form inputs; prevented by parameterised queries
- **Cross-site scripting (XSS)** — injecting malicious scripts into web pages; prevented by sanitising user input

## Worked examples

### Example — Client-side form validation

```javascript
function validateForm() {
    let age = document.getElementById("age").value;
    if (age < 0 || age > 120) {
        alert("Please enter a valid age.");
        return false;  // prevent form submission
    }
    return true;
}
```

This validation runs in the browser without contacting the server — fast feedback for the user.

## Common mistakes

- ❌ **Mistake:** Saying JavaScript runs on the server.  
  ✅ **Correction:** Standard JavaScript runs in the **browser** (client-side). Node.js is a separate runtime that allows JavaScript to run server-side, but this is a distinct context.

- ❌ **Mistake:** Saying HTML creates the visual design of a web page.  
  ✅ **Correction:** HTML defines **structure and content**; CSS defines **appearance and layout**.
