# 1.4.2 Data Structures

> **Component:** 01 — Computer Systems | **Section:** 1.4 | **Sub-section:** 1.4.2

---

## What you need to know

Data structures are ways of organising data so that it can be stored and accessed efficiently. This topic covers the key structures you must know for OCR: arrays, linked lists, stacks, queues, trees, and graphs. You also need to understand how they are implemented and what operations they support. This topic links very closely with [2.3.1 Algorithms](../../component-02-algorithms-and-programming/2.3-algorithms/2.3.1-algorithms.md).

---

## Specification points

- [ ] (a) Arrays — 1D and 2D; accessing elements by index
- [ ] (b) Records — a collection of related fields (like a row in a table)
- [ ] (c) Lists — dynamic, ordered collection; can be implemented as a linked list
- [ ] (d) Tuples — ordered, immutable sequence
- [ ] (e) Linked lists — nodes with data and pointer; singly and doubly linked
- [ ] (f) Stacks — LIFO; push, pop, peek, isEmpty, isFull operations
- [ ] (g) Queues — FIFO; enqueue, dequeue, isEmpty, isFull operations (including circular queue)
- [ ] (h) Trees — general trees; binary trees; binary search trees; tree traversals (pre-order, in-order, post-order)
- [ ] (i) Hash tables — hashing functions, collision handling
- [ ] (j) Graphs — vertices (nodes) and edges; directed and undirected; weighted; adjacency matrix vs adjacency list
- [ ] (k) Choosing an appropriate data structure for a given problem

## Key terms

| Term | Definition |
|------|-----------|
| **Array** | A fixed-size, indexed collection of elements of the same data type |
| **Record** | A collection of related fields, possibly of different data types (like a struct) |
| **Linked list** | A dynamic data structure where each node stores data and a pointer to the next node |
| **Stack** | A LIFO (Last In, First Out) data structure; items are added and removed from the top |
| **Queue** | A FIFO (First In, First Out) data structure; items added at rear, removed from front |
| **Circular queue** | A queue implemented in a fixed array where the rear pointer wraps around to the front |
| **Tree** | A hierarchical data structure with a root node; each node has zero or more child nodes |
| **Binary tree** | A tree where each node has at most two children (left and right) |
| **Binary Search Tree (BST)** | A binary tree where left child < parent < right child |
| **Hash table** | A data structure that maps keys to values using a hash function |
| **Collision** | When two keys produce the same hash value |
| **Graph** | A structure of vertices (nodes) connected by edges |
| **Directed graph** | A graph where edges have a direction (one-way connections) |
| **Weighted graph** | A graph where edges have a numerical value (e.g. distance or cost) |
| **Adjacency matrix** | A 2D array representation of a graph; matrix[i][j] = weight if edge exists |
| **Adjacency list** | A list representation of a graph; each vertex stores a list of its neighbours |
| **LIFO** | Last In, First Out — the order of a stack |
| **FIFO** | First In, First Out — the order of a queue |
| **Pointer** | A variable that stores a memory address (used in linked lists and trees) |

## Core notes

### Arrays

- Fixed size, stored in **contiguous memory** locations
- Elements accessed by **index** (usually 0-based or 1-based depending on language)
- Fast random access: O(1) — know the index, go straight to the element
- Slow insertion/deletion (shifting elements)

**1D array example:**
```
scores = [72, 85, 61, 90, 78]
scores[0] = 72,  scores[2] = 61
```

**2D array example (grid):**
```
grid[row][col]
grid[0][0] = top-left element
```

### Linked lists

- **Dynamic** — can grow and shrink at runtime
- Each **node** contains: data + pointer to next node
- **Singly linked:** pointer goes one direction only
- **Doubly linked:** each node has pointers to both next and previous nodes

```
[Data|Next] → [Data|Next] → [Data|Null]
 Node 1         Node 2       Node 3 (tail)
```

- Insertion and deletion efficient (just update pointers) — O(1) once position known
- Slow sequential search (no direct index access) — O(n)

### Stacks

**LIFO — Last In, First Out**  
Think of a stack of plates — you can only take from the top.

Operations:
- **Push** — add an item to the top
- **Pop** — remove and return the top item
- **Peek / Top** — view the top item without removing it
- **isEmpty** — check if the stack is empty
- **isFull** — check if the stack is full (for static implementations)

**Uses of stacks:**
- Call stack (function calls in a program)
- Undo/redo functionality
- Reverse Polish Notation (RPN) evaluation
- Depth-first search (backtracking)

### Queues

**FIFO — First In, First Out**  
Think of a queue at a ticket office.

Operations:
- **Enqueue** — add to the rear
- **Dequeue** — remove from the front
- **isEmpty / isFull** — status checks

**Circular queue:**
- Implemented in a fixed-size array; when rear reaches the end, it wraps to position 0
- Prevents wasted space at the front after dequeue

**Uses of queues:**
- Print job spooling
- CPU scheduling
- Breadth-first search
- Buffer for data streams

### Binary Search Trees (BST)

For every node:  
- Left subtree contains values **less than** the node
- Right subtree contains values **greater than** the node

**Inserting 8, 3, 10, 1, 6:**
```
        8
       / \
      3   10
     / \
    1   6
```

**Tree traversals:**

| Traversal | Order | Use |
|-----------|-------|-----|
| **Pre-order** | Root → Left → Right | Copying a tree |
| **In-order** | Left → Root → Right | Sorted output from BST |
| **Post-order** | Left → Right → Root | Deleting a tree; expression evaluation |

For the tree above:
- **In-order:** 1, 3, 6, 8, 10 ← gives sorted order
- **Pre-order:** 8, 3, 1, 6, 10
- **Post-order:** 1, 6, 3, 10, 8

### Hash tables

A **hash function** takes a key and returns an index (hash value):

```
index = key MOD tableSize
```

**Example:** Key = 37, table size = 10 → index = 37 MOD 10 = 7

**Collision:** Two keys map to the same index.  
**Collision handling strategies:**
- **Chaining** — each slot holds a linked list of all keys that hash there
- **Open addressing / linear probing** — if slot is taken, try slot+1, slot+2, …

### Graphs

**Directed vs undirected:**
- **Undirected:** edges have no direction (A–B means you can go A→B or B→A)
- **Directed (digraph):** edges have direction (A→B does not imply B→A)

**Weighted graphs:** edges have a numerical value (e.g. distance, cost, time)

**Adjacency matrix** (for 4-vertex weighted graph):

|   | A | B | C | D |
|---|---|---|---|---|
| **A** | 0 | 5 | 0 | 8 |
| **B** | 5 | 0 | 3 | 0 |
| **C** | 0 | 3 | 0 | 2 |
| **D** | 8 | 0 | 2 | 0 |

- Advantage: fast to check if an edge exists — O(1)
- Disadvantage: wastes space for sparse graphs — always n² space

**Adjacency list:**
```
A: [B(5), D(8)]
B: [A(5), C(3)]
C: [B(3), D(2)]
D: [A(8), C(2)]
```

- Advantage: space-efficient for sparse graphs
- Disadvantage: slower to check if a specific edge exists

### Choosing a data structure

| Need | Suitable structure |
|------|--------------------|
| Fast lookup by key | Hash table |
| Ordered data; frequent search | Binary search tree |
| LIFO access pattern | Stack |
| FIFO access pattern | Queue |
| Dynamic list, frequent insert/delete | Linked list |
| Fast random access by index | Array |
| Map connections between items | Graph |
| Hierarchical data | Tree |

## Worked examples

### Example 1 — Stack trace

Perform these operations on an empty stack. Show the stack state after each:

| Operation | Stack (top → bottom) |
|-----------|----------------------|
| Push(5) | [5] |
| Push(3) | [3, 5] |
| Push(7) | [7, 3, 5] |
| Pop() | [3, 5] — returns 7 |
| Peek() | [3, 5] — returns 3, no change |
| Pop() | [5] — returns 3 |

### Example 2 — BST insertion and in-order traversal

Insert: 15, 9, 22, 4, 11

```
         15
        /  \
       9    22
      / \
     4   11
```

In-order traversal (L → Root → R): **4, 9, 11, 15, 22** (sorted!)

### Example 3 — Hash table collision

Table size = 7. Insert keys: 10, 17, 24

- 10 MOD 7 = 3 → placed at index 3
- 17 MOD 7 = 3 → **collision!** → linear probe: try index 4 → empty → placed at 4
- 24 MOD 7 = 3 → **collision!** → try 4 (taken) → try 5 → placed at 5

## Common mistakes

- ❌ **Mistake:** Saying linked lists use contiguous memory like arrays.  
  ✅ **Correction:** Linked list nodes can be stored anywhere in memory — they are linked by **pointers**, not by position.

- ❌ **Mistake:** Confusing a stack (LIFO) and a queue (FIFO).  
  ✅ **Correction:** Stack = **Last** In, First Out (like a stack of books). Queue = **First** In, First Out (like a queue at a shop).

- ❌ **Mistake:** Saying in-order traversal always gives sorted output.  
  ✅ **Correction:** In-order traversal gives sorted output only from a **Binary Search Tree** (BST), not from a general binary tree.

- ❌ **Mistake:** Saying adjacency matrix and adjacency list are interchangeable.  
  ✅ **Correction:** Adjacency matrix wastes space for sparse graphs but gives O(1) edge lookup; adjacency list is space-efficient but O(degree) for edge lookup. Choice depends on the graph's density.

## Exam focus

- **Trace** — perform push/pop operations on a stack; enqueue/dequeue on a queue; insert into a BST
- **Describe** — the difference between a stack and a queue; how a hash table handles collisions
- **Compare** — adjacency matrix vs adjacency list; array vs linked list
- **Construct** — draw a BST from a given list; build an adjacency matrix from a graph diagram
- **Choose** — select an appropriate data structure for a described problem and justify

> 💡 BST insertion/traversal, stack traces, and queue traces are **very common exam questions**. Practise these until they feel automatic.

## Quick-check questions

1. What does LIFO stand for and which data structure uses it?
2. What is the difference between a push and a pop operation on a stack?
3. In a BST, where are values smaller than the root stored?
4. What is a collision in a hash table and how can it be resolved?
5. Give one advantage of an adjacency list over an adjacency matrix.
6. What order does in-order traversal visit nodes: root first, or leaves first?
7. Give one real-world use for a queue data structure.

<details>
<summary>Outline answers</summary>

1. Last In, First Out — the Stack.
2. Push adds an item to the top of the stack; Pop removes and returns the top item.
3. In the left subtree.
4. A collision is when two keys hash to the same index. It can be resolved by chaining (linked list at each slot) or open addressing/linear probing (try next available slot).
5. An adjacency list uses less memory for sparse graphs (only stores existing edges).
6. In-order visits left subtree first, then root, then right subtree — so left/leaves before root.
7. Any valid example: print queue / job scheduling / breadth-first search / keyboard buffer.

</details>
