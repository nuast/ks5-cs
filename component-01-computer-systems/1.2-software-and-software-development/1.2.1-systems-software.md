# 1.2.1 Systems Software

> **Component:** 01 — Computer Systems | **Section:** 1.2 | **Sub-section:** 1.2.1

---

## What you need to know

Systems software includes the programs that manage and control the computer hardware. The most important is the **operating system (OS)**. This topic covers the role of the OS and the key functions it provides, as well as utility software and the distinction between systems software and applications software.

## Key terms

| Term | Definition |
|------|-----------|
| **Operating system (OS)** | Software that manages hardware resources and provides services for application programs |
| **Kernel** | The core of the OS; runs in privileged mode and directly manages hardware |
| **Process** | A program in execution |
| **Thread** | A lightweight sub-unit of a process; multiple threads share the same process resources |
| **Scheduler** | The OS component that decides which process/thread runs next on the CPU |
| **Paging** | Dividing memory into fixed-size pages to allow non-contiguous allocation |
| **Driver** | Software that allows the OS to communicate with a specific hardware device |
| **CLI** | Command Line Interface — text-based interaction with the OS |
| **GUI** | Graphical User Interface — visual interaction using windows, icons, menus, pointer |
| **Open source** | Software whose source code is publicly available to view, modify, and distribute |
| **Closed source** | Proprietary software; source code not publicly available |

## Core notes

### Role of the operating system

The OS acts as an **intermediary** between user applications and hardware. Key functions:

1. **Memory management** — allocating RAM to processes; using virtual memory when needed
2. **Process management** — creating, scheduling, and terminating processes
3. **Device management** — using drivers to communicate with I/O hardware
4. **File management** — organising files in directories; managing access permissions
5. **Security** — authentication, access control
6. **User interface** — providing CLI or GUI for users to interact

### Process scheduling algorithms

| Algorithm | How it works | Best for |
|-----------|-------------|---------|
| **Round robin** | Each process gets equal time slices (quanta); cycles continuously | Interactive/time-sharing systems |
| **First come first served (FCFS)** | Processes run in arrival order; non-preemptive | Simple batch systems |
| **Shortest job first (SJF)** | Shortest estimated job runs first | Minimising average waiting time |
| **Multi-level feedback queue** | Multiple queues with different priorities; processes move between queues | Modern general-purpose OSes |

### Open source vs closed source

| Feature | Open source | Closed source |
|---------|------------|--------------|
| **Source code** | Publicly available | Hidden / proprietary |
| **Cost** | Usually free | Often paid |
| **Customisability** | Can be modified | Cannot be modified |
| **Support** | Community-driven | Commercial vendor support |
| **Security** | Many eyes find bugs; also exposes vulnerabilities | Vendor responsible; vulnerabilities hidden |
| **Examples** | Linux, Firefox, LibreOffice | Windows, macOS, Microsoft Office |

### Utility software

| Utility | Purpose |
|---------|---------|
| **Disk defragmenter** | Rearranges fragmented files on HDD to improve access speed |
| **Antivirus/malware scanner** | Detects and removes malicious software |
| **Backup software** | Copies data to a secondary location for recovery |
| **Compression software** | Reduces file sizes for storage or transmission |
| **Disk formatter** | Prepares a storage medium with a file system |
| **Encryption software** | Encrypts data for security |

## Worked examples

### Example — Round robin scheduling

Processes arrive: P1 (burst: 8ms), P2 (burst: 4ms), P3 (burst: 3ms). Time quantum = 3ms.

| Time | Running | Remaining (P1, P2, P3) |
|------|---------|------------------------|
| 0–3 | P1 | 5, 4, 3 |
| 3–6 | P2 | 5, 1, 3 |
| 6–9 | P3 | 5, 1, 0 → P3 finishes |
| 9–12 | P1 | 2, 1, — |
| 12–13 | P2 | 2, 0 → P2 finishes |
| 13–15 | P1 | 0 → P1 finishes |

## Common mistakes

- ❌ **Mistake:** Saying open source software is always more secure than closed source.  
  ✅ **Correction:** Open source benefits from many people finding bugs, but also exposes code to attackers — the answer depends on how actively the code is maintained.

- ❌ **Mistake:** Confusing a process and a thread.  
  ✅ **Correction:** A thread is a sub-unit of a process. Multiple threads share the same process resources (memory space); separate processes have separate memory.

## Quick-check questions

1. Name four functions of an operating system.
2. What is the difference between a process and a thread?
3. Describe how round robin scheduling works.
4. Give one advantage and one disadvantage of open source software.
5. What does a device driver do?

<details>
<summary>Outline answers</summary>

1. Any four: memory management, process management, device management, file management, security, user interface provision.
2. A process is a program in execution with its own memory space; a thread is a sub-unit of a process that shares the process's memory.
3. Each process is given equal time slices (quanta) on the CPU in rotation; if a process does not finish in its slice, it is placed at the back of the queue.
4. Advantage: free/customisable; Disadvantage: community support only / source code visible to attackers.
5. A driver allows the OS to communicate with a specific hardware device by translating OS commands into device-specific signals.

</details>
