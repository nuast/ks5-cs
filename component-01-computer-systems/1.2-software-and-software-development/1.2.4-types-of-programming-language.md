# 1.2.4 Types of Programming Language

> **Component:** 01 — Computer Systems | **Section:** 1.2 | **Sub-section:** 1.2.4

---

## What you need to know

Programming languages exist at different **levels of abstraction** — from low-level code that is close to what the hardware understands, to high-level code that is closer to human language. You also need to understand different **programming paradigms** — the different ways of thinking about and structuring programs.

## Key terms

| Term | Definition |
|------|-----------|
| **Machine code** | Binary instructions executed directly by the CPU |
| **Assembly language** | Low-level language using human-readable mnemonics (e.g. MOV, ADD) translated by an assembler |
| **High-level language** | Language close to English; translated by compiler or interpreter; hardware-independent |
| **Paradigm** | A style or approach to programming |
| **Procedural** | Programming using sequences of instructions, procedures, and control flow |
| **OOP** | Object-Oriented Programming — organising code around objects with data and behaviour |
| **Class** | A blueprint or template for creating objects |
| **Object** | An instance of a class |
| **Encapsulation** | Hiding internal object data behind methods (getters/setters) |
| **Inheritance** | A class (child) inherits attributes and methods from another class (parent) |
| **Polymorphism** | Different objects responding differently to the same method call |
| **Declarative** | Describing *what* you want rather than *how* to do it (e.g. SQL, Prolog) |

## Core notes

### Low-level vs high-level languages

| Feature | Low-level (machine/assembly) | High-level |
|---------|----------------------------|-----------|
| **Readability** | Hard to read | Close to English |
| **Portability** | Machine-specific | Platform-independent |
| **Speed** | Fast — close to hardware | Slightly slower due to translation |
| **Memory control** | Direct control | Abstracted |
| **Use case** | Device drivers, OS kernels, embedded systems | General applications, web, AI |

### Procedural programming

- Programs are sequences of instructions (statements)
- Uses **procedures/functions** for reusability
- Uses **sequence**, **selection** (IF), **iteration** (loops)
- Examples: Python (procedural style), Pascal, C

### Object-oriented programming (OOP)

Programs are built from **objects** that combine data (attributes) and behaviour (methods).

**Key concepts:**

| Concept | Explanation | Example |
|---------|------------|---------|
| **Class** | Template/blueprint | `class Dog:` |
| **Object** | Instance of a class | `myDog = Dog("Rex")` |
| **Encapsulation** | Hide data inside the class; expose via methods | Private attribute `__name`; getter `getName()` |
| **Inheritance** | Child class extends parent class | `class GoldenRetriever(Dog):` |
| **Polymorphism** | Same method name, different behaviour | `speak()` returns "Woof" for Dog; "Meow" for Cat |

**Advantages of OOP:**
- Code reuse through inheritance
- Modular — objects can be developed and tested independently
- Encapsulation makes code more secure and maintainable

### Declarative programming

- Programmer states **what** the answer should look like, not **how** to find it
- Examples:
  - **SQL** — "SELECT name FROM students WHERE grade > 70"
  - **Prolog** — state facts and rules; query the system
  - **HTML** — declares what content exists, not how to render it

---

## Common mistakes

- ❌ **Mistake:** Saying OOP is always the best paradigm.  
  ✅ **Correction:** The best paradigm depends on the problem. Declarative (SQL) is better for database queries; procedural may be cleaner for simple scripts.

- ❌ **Mistake:** Confusing a class and an object.  
  ✅ **Correction:** A **class** is the blueprint; an **object** is a specific instance created from that blueprint.

## Quick-check questions

1. What is the difference between machine code and assembly language?
2. Give two advantages of using a high-level language over assembly language.
3. What is encapsulation in OOP?
4. Give an example of inheritance in OOP.
5. Why is SQL considered a declarative language?

<details>
<summary>Outline answers</summary>

1. Machine code is binary (0s and 1s) executed directly by the CPU; assembly language uses human-readable mnemonics that are translated by an assembler.
2. Any two: more readable / platform-independent / faster to develop / easier to maintain / closer to natural language.
3. Hiding the internal data of an object and only allowing access through defined methods (getters/setters).
4. E.g. class Cat inherits from class Animal — Cat has all Animal attributes plus its own.
5. SQL describes *what* data to retrieve, not *how* the database engine should find it.

</details>
