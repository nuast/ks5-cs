# 1.2.2 Applications Generation

## What you need to know

This topic covers how application software is generated and deployed. You need to understand the nature of applications software, how it is written and translated for execution, and how modern software is delivered (including via app stores and the cloud). It links closely with 1.2.4 (types of programming language).

## Key terms

| Term | Definition |
|------|-----------|
| **General-purpose software** | Software designed for a wide range of tasks (e.g. word processor, spreadsheet) |
| **Special-purpose software** | Software designed for one specific task (e.g. an accounting package, photo editing) |
| **Bespoke software** | Custom-built software for a specific client |
| **Compiler** | Translates the entire source code into machine code before execution; produces a standalone executable |
| **Interpreter** | Translates and executes source code line by line at runtime |
| **Assembler** | Translates assembly language into machine code |
| **Lexical analysis** | First stage of compilation — tokenises the source code into meaningful units |
| **Syntax analysis** | Checks that the token sequence conforms to the grammar rules of the language |
| **Code generation** | Produces machine code (or intermediate code) from the syntax tree |
| **Optimisation** | Improves the generated code for speed or size |
| **IDE** | Integrated Development Environment — a software application providing tools for coding |
| **Library** | Pre-written, reusable code modules that can be included in a program |
| **Static linking** | Library code is copied into the executable at compile time |
| **Dynamic linking** | Library code is loaded at runtime; multiple programs share the library |
| **SaaS** | Software as a Service — applications hosted and accessed via the internet |

## Core notes

### Types of application software

| Type | Description | Example |
|------|------------|---------|
| **General-purpose** | Can be used for many different tasks | Microsoft Word, LibreOffice Calc |
| **Special-purpose** | Designed for one specific function | Flight booking system, hospital patient records |
| **Bespoke** | Custom built for one client's exact needs | Custom warehouse management system |

**Bespoke vs off-the-shelf:**

| | Bespoke | Off-the-shelf |
|-|---------|--------------|
| **Cost** | Expensive to develop | Cheaper to buy |
| **Fit to requirements** | Exact fit | May not meet all needs |
| **Support** | Developer provides support | Vendor provides support |
| **Development time** | Long | Ready immediately |

### Translators

**Compiler:**
- Reads entire source code and produces a machine code executable
- Executable runs directly without the source code or compiler
- Errors reported after the entire code is analysed
- Faster execution (code already translated)
- Harder to debug (errors may be cryptic)

**Interpreter:**
- Translates and runs code line by line at runtime
- No separate executable produced
- Errors reported as they are encountered — easier to debug
- Slower execution (translating on the fly)
- Source code (or intermediate code) required to run

**Assembler:**
- Translates **assembly language** (human-readable mnemonics) into machine code
- One-to-one relationship between assembly instructions and machine code

### Stages of compilation

```
Source code
    ↓ Lexical analysis (tokenisation)
Tokens
    ↓ Syntax analysis (parsing — builds parse tree, checks grammar)
Parse tree / AST
    ↓ Semantic analysis (checks meaning — e.g. type checking)
    ↓ Code generation
Intermediate / machine code
    ↓ Optimisation
Optimised machine code
```

### IDEs (Integrated Development Environments)

An IDE brings together tools for writing, testing, and debugging code. Key features:

| Feature | Purpose |
|---------|---------|
| **Code editor** | Syntax highlighting, auto-indentation, auto-completion |
| **Compiler/interpreter** | Translate and run code from within the IDE |
| **Debugger** | Set breakpoints; step through code; inspect variable values |
| **Error highlighting** | Marks syntax errors as you type |
| **Version control integration** | Interact with Git etc. from within the IDE |
| **Refactoring tools** | Rename variables, extract functions automatically |

### Libraries

- **Static linking:** Library code copied into the executable → larger file; self-contained; no dependency issues
- **Dynamic linking:** Library loaded at runtime → smaller executable; library updates apply automatically; multiple programs share one copy in memory

## Common mistakes

- ❌ **Mistake:** Saying a compiler translates code line by line.  
  ✅ **Correction:** A compiler translates the **entire** program before execution. An **interpreter** translates line by line.

- ❌ **Mistake:** Saying interpreted programs are always better for debugging.  
  ✅ **Correction:** Interpreters do make it easier to find runtime errors (they stop at the error line), but compiled code can include debug symbols for use with a debugger too.

## Quick-check questions

1. What is the difference between a compiler and an interpreter?
2. List the stages of compilation in order.
3. What is an IDE and name two features it provides.
4. Give one advantage of bespoke software over off-the-shelf software.
5. What is the difference between static and dynamic linking?

<details>
<summary>Outline answers</summary>

1. A compiler translates the whole program before execution, producing an executable; an interpreter translates and runs code line by line at runtime.
2. Lexical analysis → Syntax analysis → (Semantic analysis) → Code generation → Optimisation.
3. An IDE is a software application providing an integrated environment for writing and testing code. Features: code editor / debugger / compiler-interpreter / error highlighting / version control integration.
4. Any valid point: exact fit to requirements / no unnecessary features / competitive advantage / better security tailored to needs.
5. Static: library copied into executable at compile time. Dynamic: library loaded from disk at runtime; multiple programs share it.

</details>
