# 2.1.1 Thinking Abstractly

> **Component:** 02 — Algorithms and Programming | **Section:** 2.1 | **Sub-section:** 2.1.1

---

## What you need to know

Abstraction is one of the most fundamental ideas in computer science. It means **hiding unnecessary detail** so that you can focus on what is important. You need to understand what abstraction means, how it is used in computing and problem-solving, and how to create abstractions from real-world problems.

## Key terms

| Term | Definition |
|------|-----------|
| **Abstraction** | Removing unnecessary detail from a problem or model to focus on what is important |
| **Representational abstraction** | Creating a model that only includes the information relevant to solving the problem |
| **Generalisation** | Grouping objects or problems by their shared characteristics |
| **Procedural abstraction** | Calling a function without knowing its internal implementation |
| **Data abstraction** | Using a data structure (e.g. stack, queue) without knowing how it is implemented |
| **Problem abstraction / reduction** | Recognising that a new problem is equivalent to a simpler or already-solved problem |
| **Layer of abstraction** | A level in a hierarchy where each level hides the complexity of the layer below |
| **Model** | A simplified representation of a real-world system |

---

## Core notes

### What is abstraction?

Abstraction means **focusing on what matters** by hiding complexity. In everyday life:
- A map is an abstraction of real geography — it shows roads but not every tree
- A recipe is an abstraction of cooking — steps without chemistry details

In computing:
- A programming language abstracts machine code
- A function/procedure abstracts the steps it contains
- A class abstracts the data and behaviour of an object

### Types of abstraction

**Representational abstraction:**  
Remove irrelevant detail from a real-world model.  
Example: Modelling a school timetable — relevant: rooms, times, subjects, teachers. Irrelevant: colour of chairs, weather outside.

**Abstraction by generalisation:**  
Group things by common features → enables code reuse.  
Example: A `Shape` class in OOP — Circle, Square, Triangle are all Shapes.

**Procedural abstraction:**  
Call `sort(myList)` without knowing the algorithm used.  
The caller does not need to know whether it uses merge sort, quick sort, etc.

**Data abstraction:**  
Use a stack with `push()`, `pop()`, `peek()` without knowing whether it is implemented as an array or linked list.

**Problem abstraction / reduction:**  
"Routing a delivery van" is an instance of the Travelling Salesman Problem — already studied by mathematicians. We can apply known algorithms.

### Layers of abstraction

| Layer | Example |
|-------|---------|
| High-level language | Python, Java |
| Assembly language | MOV, ADD, JMP |
| Machine code | 10110001 11000011 |
| Logic gates / hardware | AND, OR, NOT circuits |

Each layer **hides** the complexity of the layer below.

## Common mistakes

- ❌ **Mistake:** Thinking abstraction means simplifying a problem by removing all detail.  
  ✅ **Correction:** Abstraction removes **irrelevant** detail — but preserves all detail that **matters** for the purpose.

- ❌ **Mistake:** Confusing abstraction with decomposition.  
  ✅ **Correction:** Decomposition (see 2.1.3) breaks a problem into parts. Abstraction removes irrelevant detail from a problem or model.

## Quick-check questions

1. What does abstraction mean in computing?
2. Give one example of abstraction in everyday life.
3. What is procedural abstraction?
4. What is the difference between data abstraction and procedural abstraction?
5. Give an example of layers of abstraction in a computer system.

<details>
<summary>Outline answers</summary>

1. Removing unnecessary or irrelevant detail from a problem or model to focus on what matters.
2. A map / a recipe / a menu in a restaurant (any reasonable real-world example).
3. Calling a function/procedure without needing to know its internal implementation.
4. Data abstraction hides the implementation of a data structure; procedural abstraction hides the implementation of a function/subroutine.
5. High-level language → assembly language → machine code → logic gates (each level hides the complexity of the one below).
