# 2.1.4 Thinking Logically

> **Component:** 02 — Algorithms and Programming | **Section:** 2.1 | **Sub-section:** 2.1.4

## What you need to know

Thinking logically is the ability to work out which conditions lead to which outcomes — and to use this to make decisions in programs and problem-solving. This topic overlaps with Boolean algebra (1.4.3) and algorithmic problem-solving.

## Key terms

| Term | Definition |
|------|-----------|
| **Condition** | A Boolean expression that evaluates to True or False |
| **Decision** | A point in an algorithm where a path is chosen based on a condition |
| **Logical operator** | AND, OR, NOT — used to combine Boolean conditions |
| **Short-circuit evaluation** | Stopping evaluation of a Boolean expression as soon as the result is known |
| **Invariant** | A condition that remains true throughout a loop or algorithm |

---

## Core notes

### Conditions and decisions in programs

Every `IF`, `WHILE`, and `FOR` statement involves a **condition**:

```
IF age >= 18 AND hasID = TRUE THEN
    PRINT "Access granted"
ELSE
    PRINT "Access denied"
ENDIF
```

**Logical operators in conditions:**
- `AND` — both conditions must be True
- `OR` — at least one must be True
- `NOT` — inverts the condition

### Evaluating algorithm correctness

When checking if an algorithm is correct:
- **Trace** through it with sample inputs
- Check **boundary cases** (what happens at edges of input ranges)
- Check **error cases** (what happens with invalid input)
- Look for **logic errors** (conditions that are the wrong way round)

**Common logical errors:**
- Using `>` instead of `>=` (off-by-one errors)
- Wrong loop termination condition (infinite loop or early exit)
- Incorrect compound condition (`AND` vs `OR` confusion)

### Loop invariants

An **invariant** is a property that holds true at the start of every iteration of a loop. Understanding invariants helps prove an algorithm is correct.

Example for linear search:
- **Invariant:** After i iterations, the target has not been found in arr[0..i-1]

---

## Common mistakes

- ❌ **Mistake:** Confusing AND and OR when writing conditions.  
  ✅ **Correction:** Test with specific values — "if the user must be over 18 AND a member," both must be true simultaneously.

- ❌ **Mistake:** Off-by-one errors in loop boundaries.  
  ✅ **Correction:** Trace through the first and last iterations carefully to check the boundary condition.

## Quick-check questions

1. What does a Boolean condition evaluate to?
2. Give an example of using AND in a program condition.
3. What is an off-by-one error?
4. What is a loop invariant?

<details>
<summary>Outline answers</summary>

1. True or False (1 or 0).
2. `IF x > 0 AND x < 100 THEN` (any valid example).
3. A logic error where a loop runs one time too many or too few, often due to using > instead of >= (or vice versa).
4. A condition that holds true at the start of every iteration of a loop, used to reason about correctness.

</details>

```
count ← 0
FOR i ← 1 TO 9
    IF arr[i] >= 50 THEN
        count ← count + 1
    ENDIF
ENDFOR
```
