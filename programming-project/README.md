# Component 03 — Programming Project (H446/03)

The programming project is **non-examined assessment (NEA)** worth **70 marks (30% of A-Level)**.

You design, develop, test, and evaluate a substantial software solution to a problem of your choosing (subject to teacher and OCR approval). Unlike the written papers, this is completed over an extended period and submitted as a report with your working program.

---

## Overview

| Aspect | Detail |
|--------|--------|
| **Weighting** | 30% of A-Level |
| **Marks** | 70 marks |
| **Submission** | Source code + written report |
| **Authentication** | Signed by teacher confirming it is your own work |

---

## Assessment objectives

The project is marked against these criteria:

- **Analysis** *(9 marks)* — Problem identification, stakeholder research, requirements specification
- **Design** *(15 marks)* — Solution design, decomposition, data structures, algorithms, UI, test plan
- **Technical solution** *(30 marks)* — Quality and complexity of your code; use of appropriate techniques
- **Testing and evaluation** *(9 marks)* — Evidence-based testing, evaluation against requirements, limitations
- **Evaluation** *(7 marks)* — Reflective evaluation of the project and potential improvements

---

## Tips for a strong project

### Choosing a problem
- Pick something **genuinely complex** — the solution must demonstrate A-Level programming skill.
- Avoid trivially simple CRUD apps; aim for a system with algorithms, data structures, and non-trivial logic.
- Ensure you have a real or realistic stakeholder to interview.

### Analysis phase
- Clearly identify the **current system / problem**.
- Interview your stakeholder and document their requirements.
- Produce **numbered, testable requirements** (e.g. "The system shall…").

### Design phase
- Decompose the problem into sub-problems (see [2.1.3 Thinking procedurally](../algorithms-programming/2.1-elements-of-computational-thinking/2.1.3-thinking-procedurally.md)).
- Design your data structures before writing code.
- Write a detailed **test plan** before testing.

### Technical solution
- Use techniques from the specification: recursion, file I/O, OOP, complex data structures, sorting/searching algorithms.
- Comment your code clearly.
- Aim for modular, well-structured code.

### Testing
- Use your pre-written test plan; record actual vs expected results.
- Include **normal, boundary, and erroneous** test cases.

### Evaluation
- Refer back to your original requirements — did you meet them?
- Be honest about limitations and suggest genuine improvements.
