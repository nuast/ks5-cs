## Key terms

| Term | Definition |
|------|-----------|
| **Procedure** | A named subroutine that performs a task; does not return a value |
| **Function** | A named subroutine that returns a value |
| **Parameter** | A variable passed into a subroutine |
| **Return value** | The value a function sends back to the caller |
| **Local variable** | A variable defined inside a subroutine; only accessible within it |
| **Global variable** | A variable accessible from anywhere in the program |
| **Recursion** | A subroutine that calls itself |
| **Base case** | The condition that stops a recursive function from calling itself again |
| **Recursive case** | The part of a recursive function that calls itself (with a simpler input) |
| **Stack frame** | The area of the call stack used to store a subroutine's local variables and return address |
| **Exception** | An error or unexpected event at runtime |
| **Exception handling** | Code that catches and responds to exceptions without crashing the program |

## Core notes

### Subroutines — functions and procedures

```
// Procedure — does not return a value
PROCEDURE greet(name)
    PRINT "Hello, " + name
ENDPROCEDURE

// Function — returns a value
FUNCTION square(n)
    RETURN n * n
ENDFUNCTION

// Calling them
greet("Alice")       // prints "Hello, Alice"
result ← square(5)  // result = 25
```

**Scope:**
- **Local variables:** only exist inside the subroutine; lost when the subroutine ends
- **Global variables:** accessible anywhere; use sparingly (makes code harder to maintain)

### Recursion

A recursive function calls itself with a simpler version of the problem until a **base case** is reached.

```
FUNCTION factorial(n)
    IF n = 0 THEN
        RETURN 1          // base case
    ELSE
        RETURN n * factorial(n - 1)  // recursive case
    ENDIF
ENDFUNCTION
```

`factorial(4)`:
→ 4 × factorial(3) → 4 × 3 × factorial(2) → 4 × 3 × 2 × factorial(1) → 4 × 3 × 2 × 1 × factorial(0) → 4 × 3 × 2 × 1 × 1 = **24**

**Advantages of recursion:**
- Elegant solution for naturally recursive problems (trees, fractals, divide and conquer)
- Code can be shorter and more readable

**Disadvantages:**
- Each call uses a stack frame → stack overflow if recursion is too deep
- Slower than iterative solutions due to function call overhead
- Harder to trace and debug

### Exception handling

```
TRY
    number ← INT(userinput("Enter a number: "))
    PRINT 10 / number
CATCH DivisionByZeroError
    PRINT "Cannot divide by zero"
CATCH ValueError
    PRINT "Please enter a valid integer"
FINALLY
    PRINT "Done"
ENDTRY
```

- **TRY:** attempt the risky code
- **CATCH:** handle a specific error type
- **FINALLY:** always runs, whether or not an error occurred

### File handling

```
// Reading a file
file ← OPEN("data.txt", "read")
WHILE NOT file.endOfFile() DO
    line ← file.readLine()
    PRINT line
ENDWHILE
file.close()

// Writing to a file
file ← OPEN("output.txt", "write")
file.writeLine("Hello, file!")
file.close()
```

**Modes:** read, write (overwrites), append (adds to end)

### String handling

```
str ← "Hello, World!"
LEN(str)                  // 13
str.substring(7, 5)       // "World"
str.upper()               // "HELLO, WORLD!"
str.lower()               // "hello, world!"
str + " Goodbye"          // concatenation
INT("42")                 // convert string "42" to integer 42
STR(99)                   // convert integer 99 to string "99"
```

## Worked examples

### Example — Recursive binary search

```
FUNCTION recursiveBinarySearch(arr, target, low, high)
    IF low > high THEN
        RETURN -1                    // base case: not found
    ENDIF
    mid ← (low + high) DIV 2
    IF arr[mid] = target THEN
        RETURN mid                   // base case: found
    ELSE IF arr[mid] < target THEN
        RETURN recursiveBinarySearch(arr, target, mid + 1, high)
    ELSE
        RETURN recursiveBinarySearch(arr, target, low, mid - 1)
    ENDIF
ENDFUNCTION
```

### Example — OOP (class and objects)

```
CLASS Animal
    PRIVATE name
    PRIVATE sound

    CONSTRUCTOR(name, sound)
        this.name ← name
        this.sound ← sound
    ENDCONSTRUCTOR

    FUNCTION makeSound()
        RETURN this.name + " says " + this.sound
    ENDFUNCTION
ENDCLASS

CLASS Dog EXTENDS Animal
    CONSTRUCTOR(name)
        SUPER(name, "Woof")
    ENDCONSTRUCTOR
ENDCLASS

myDog ← NEW Dog("Rex")
PRINT myDog.makeSound()   // Rex says Woof
```

## Common mistakes

- ❌ **Mistake:** Forgetting the base case in a recursive function.  
  ✅ **Correction:** Every recursive function **must** have a base case — without one, recursion continues infinitely until a stack overflow.

- ❌ **Mistake:** Using global variables inside functions instead of parameters.  
  ✅ **Correction:** Use parameters to pass data into functions. Global variables make code hard to test and maintain.

## Quick-check questions

1. What is the difference between a procedure and a function?
2. What is a base case in a recursive function?
3. Why can deep recursion cause a stack overflow?
4. What is the purpose of the `FINALLY` block in exception handling?
5. What is the difference between `write` and `append` mode when opening a file?

<details>
<summary>Outline answers</summary>

1. A procedure performs a task without returning a value; a function performs a task and returns a value to the caller.
2. The condition at which a recursive function stops calling itself and returns a value directly.
3. Each recursive call adds a frame to the call stack. If the recursion is too deep, the stack runs out of space.
4. The FINALLY block always executes, whether or not an exception occurred — used for cleanup (e.g. closing files).
5. Write mode: creates a new file or overwrites an existing one. Append mode: adds to the end of an existing file without overwriting.

</details>
