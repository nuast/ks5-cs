# 2.2.2 Computational Methods

> **Component:** 02 — Algorithms and Programming | **Section:** 2.2 | **Sub-section:** 2.2.2

## What you need to know

Computational methods are general approaches to solving computational problems. You need to understand several key strategies, when they apply, and be able to explain and apply them to problems. This topic also asks you to think about whether a problem is computationally solvable.

## Key terms

| Term | Definition |
|------|-----------|
| **Computable problem** | A problem that can be solved by an algorithm in a finite number of steps |
| **Intractable problem** | A problem that is theoretically solvable but not in a reasonable time for large inputs |
| **Halting problem** | A well-known undecidable problem: determining whether an arbitrary program will halt |
| **Divide and conquer** | Splitting a problem into independent sub-problems, solving each, and combining results |
| **Backtracking** | Incrementally building a solution and abandoning (backtracking) when a dead end is reached |
| **Heuristic** | An approximate method that finds a good (not necessarily optimal) solution faster |
| **Data mining** | Extracting useful patterns or knowledge from large datasets |
| **Visualisation** | Representing data or a problem graphically to aid understanding or solution |
| **NP problem** | A problem whose solution can be verified in polynomial time, but may not be solvable in polynomial time |

## Core notes

### Solvability

Not all problems are solvable by computation:
- **Decidable problems:** can always be solved algorithmically (e.g. sorting, searching)
- **Undecidable problems:** no algorithm can always determine the answer (e.g. the **halting problem**)
- **Intractable problems:** theoretically solvable but require impractical time for large inputs (e.g. Travelling Salesman Problem with many cities — O(n!))

### Divide and conquer

Break the problem into sub-problems of the same type → solve each → combine results.

**Examples:** Merge sort, quick sort, binary search, Karatsuba multiplication

```
FUNCTION mergeSort(arr)
    IF LEN(arr) <= 1 THEN RETURN arr ENDIF
    mid ← LEN(arr) DIV 2
    left ← mergeSort(arr[0 .. mid - 1])    // divide
    right ← mergeSort(arr[mid .. end])      // divide
    RETURN merge(left, right)               // combine
ENDFUNCTION
```

### Backtracking

Try all possibilities systematically, abandoning a path as soon as it cannot lead to a valid solution.

**Classic example — solving a maze:**
1. Move forward
2. If blocked → go back (backtrack) and try another direction
3. If all directions fail → backtrack further

**Other examples:** Sudoku solvers, N-queens problem, pathfinding in games

```
FUNCTION solve(board, row)
    IF row = N THEN RETURN TRUE ENDIF    // all rows placed — solution found
    FOR col ← 0 TO N - 1
        IF isValid(board, row, col) THEN
            board[row] ← col
            IF solve(board, row + 1) THEN RETURN TRUE ENDIF
            board[row] ← -1              // backtrack
        ENDIF
    ENDFOR
    RETURN FALSE
ENDFUNCTION
```

### Heuristics

For intractable problems, heuristics find a **good** solution quickly without guaranteeing the **best** solution.

**Example — Travelling Salesman Problem (TSP):**
- Exact solution requires checking all routes: O(n!) — impossible for large n
- Heuristic (nearest neighbour): always go to the nearest unvisited city — fast but may not give optimal route

**Other heuristic examples:**
- A* algorithm uses a heuristic to guide pathfinding
- Genetic algorithms evolve solutions over generations
- Simulated annealing

**Trade-off:** Speed vs optimality — heuristics accept a "good enough" answer when perfect is infeasible.

### Data mining

Techniques for finding patterns, correlations, or knowledge in large datasets:
- **Clustering** — grouping similar data points
- **Classification** — assigning data points to predefined categories
- **Association rules** — finding items that often appear together (e.g. market basket analysis: "customers who buy X also buy Y")

**Applications:** Fraud detection, medical diagnosis, targeted advertising, recommendation systems

### Visualisation

Using visual representations to understand data or problems:
- **Graphs and charts** — reveal trends, outliers, distributions
- **Network diagrams** — visualise connections (e.g. road networks, social networks)
- **Flowcharts** — visualise algorithm flow
- **Heat maps** — show density or frequency

Visualisation helps identify patterns that are not obvious in raw data and helps communicate findings.

## Worked examples

### Example — Backtracking: N-queens

Place N queens on an N×N board so no two queens attack each other.

For N=4, one solution:
```
. Q . .
. . . Q
Q . . .
. . Q .
```

Backtracking tries each column for row 1, then row 2, etc. If a conflict is detected, it backtracks and tries the next column.

### Example — Heuristic for TSP

Cities: A, B, C, D. Distances:

|   | A | B | C | D |
|---|---|---|---|---|
| A | — | 10 | 15 | 20 |
| B | 10 | — | 35 | 25 |
| C | 15 | 35 | — | 30 |
| D | 20 | 25 | 30 | — |

Nearest neighbour from A: A→B(10)→D(25)→C(30)→A(15) = 80  
(Optimal may be different, but this is a reasonable heuristic result quickly.)

## Common mistakes

- ❌ **Mistake:** Saying intractable problems cannot be solved.  
  ✅ **Correction:** Intractable problems **can** be solved in principle — but not in a reasonable time for large inputs. Heuristics are used instead.

- ❌ **Mistake:** Confusing backtracking with brute force.  
  ✅ **Correction:** Brute force tries every possibility exhaustively. Backtracking **prunes** the search space — it abandons paths as soon as they cannot work, making it much more efficient.

## Quick-check questions

1. What is the difference between a decidable and an undecidable problem?
2. What is an intractable problem?
3. Give an example of a divide and conquer algorithm.
4. What is backtracking and when is it used?
5. Why are heuristics used for some problems?

<details>
<summary>Outline answers</summary>

1. Decidable: there is an algorithm that always gives a correct answer. Undecidable: no algorithm can always determine the answer.
2. A problem that is theoretically solvable but not in a practical/reasonable time for large inputs.
3. Merge sort / quick sort / binary search / Karatsuba multiplication.
4. Backtracking builds a solution incrementally and abandons a path as soon as it is determined not to lead to a valid solution; used for constraint satisfaction problems (Sudoku, N-queens, maze solving).
5. For intractable problems, an exact solution would take too long; heuristics find a good (not necessarily optimal) solution in a reasonable time.

</details>
