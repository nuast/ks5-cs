# 1.1.1 Structure and function of the processor

> **Component:** 01 — Computer Systems | **Section:** 1.1 | **Sub-section:** 1.1.1

---

## What you need to know

The processor (CPU) is the part of a computer that carries out instructions. This topic covers how the CPU is structured and how it works — specifically the **fetch-decode-execute cycle**, the key **registers**, and factors that affect how fast a processor runs. This is one of the most frequently examined topics in Component 01.

## Key terms

| Term | Definition |
|------|-----------|
| **ALU** | Arithmetic Logic Unit — performs arithmetic (add, subtract) and logical (AND, OR, NOT, compare) operations |
| **Control Unit (CU)** | Directs the operation of the processor; decodes instructions and coordinates the ALU, registers, and memory |
| **Program Counter (PC)** | Holds the memory address of the **next** instruction to be fetched |
| **Memory Address Register (MAR)** | Holds the address of the memory location currently being read from or written to |
| **Memory Data Register (MDR)** | Holds the data that has just been fetched from, or is about to be written to, memory |
| **Current Instruction Register (CIR)** | Holds the instruction currently being decoded and executed |
| **Accumulator** | General-purpose register that holds the result of ALU operations |
| **Clock speed** | The number of fetch-decode-execute cycles per second, measured in GHz |
| **Cache** | Small, fast memory built into or close to the CPU that stores frequently used data/instructions |
| **Pipelining** | A technique where multiple instructions are overlapped in execution — while one is being executed, the next is being decoded and the one after that is being fetched |
| **Interrupt** | A signal sent to the CPU by hardware or software, requesting attention |
| **Interrupt Service Routine (ISR)** | The program run in response to an interrupt |

## Core notes

### The CPU components

**Arithmetic Logic Unit (ALU)**
- Performs all calculations: addition, subtraction, multiplication, division
- Performs logical comparisons: `=`, `<`, `>`, `AND`, `OR`, `NOT`
- Results are typically stored in the **accumulator**

**Control Unit (CU)**
- Sends control signals to all other components
- Decodes instructions from the CIR
- Controls the timing and sequencing of operations
- Does **not** process data itself

**Registers**
- Tiny, extremely fast storage locations inside the CPU
- Each has a specific role (see Key terms above)

### The fetch-decode-execute cycle

This is the fundamental operation of any processor.

**1. Fetch**
1. The address in the **PC** is copied to the **MAR**
2. The instruction at that address is fetched from memory into the **MDR** (via the address bus and data bus)
3. The content of the **MDR** is copied to the **CIR**
4. The **PC** is incremented by 1 (ready for the next instruction)

**2. Decode**
- The **CU** decodes (interprets) the instruction held in the **CIR**
- It identifies the **opcode** (what to do) and the **operand** (what to do it with/to)

**3. Execute**
- The CU sends control signals to carry out the instruction
- The ALU performs any arithmetic/logic
- Results are stored (in the accumulator, a register, or back in memory)

The cycle then repeats — fetch the next instruction, decode, execute…

### Factors affecting performance

| Factor | Effect on performance |
|--------|-----------------------|
| **Clock speed** | Higher GHz = more cycles per second = faster execution |
| **Number of cores** | More cores = more instructions can be processed simultaneously (true parallelism) |
| **Cache size** | Larger cache = more data stored close to CPU = fewer slow RAM accesses |
| **Cache levels** | L1 is fastest and smallest; L2 is larger but slower; L3 is even larger but slower still |
| **Word length** | Wider word = more data processed per instruction (e.g. 64-bit vs 32-bit) |

### Pipelining

Instead of waiting for one instruction to fully complete before starting the next, the CPU overlaps stages:

```
Time →       T1      T2      T3      T4      T5
Instruction 1: Fetch | Decode | Execute
Instruction 2:        | Fetch  | Decode  | Execute
Instruction 3:                 | Fetch   | Decode  | Execute
```

- This keeps all stages of the CPU busy at once
- Improves **throughput** (instructions completed per second)
- **Problem:** branch instructions (if/else) can cause a **pipeline flush** — the pre-fetched instructions may be wrong

### Interrupt handling

An **interrupt** is a signal that tells the CPU to pause its current task and deal with something urgent (e.g. hardware error, I/O completion, timer).

**After each FDE cycle, the CPU checks for interrupts:**

1. If no interrupt (or interrupt priority too low) → fetch next instruction and continue
2. If interrupt (with sufficient priority):
   - Save current state (PC and registers) to the **stack**
   - Run the **Interrupt Service Routine (ISR)**
   - Restore the saved state from the stack
   - Continue from where it left off

## Worked examples

### Example 1 — Tracing the FDE cycle

Memory contents:

| Address | Instruction |
|---------|------------|
| 100 | LOAD 200 |
| 101 | ADD 201 |

PC starts at 100.

**Cycle 1 — Fetch:**
- MAR ← 100 (copied from PC)
- MDR ← LOAD 200 (fetched from address 100)
- CIR ← LOAD 200
- PC ← 101

**Cycle 1 — Decode:**
- CU identifies opcode: LOAD; operand: 200

**Cycle 1 — Execute:**
- MAR ← 200
- MDR ← [contents of address 200]
- Accumulator ← value from MDR

**Cycle 2 — Fetch:**
- MAR ← 101; MDR ← ADD 201; CIR ← ADD 201; PC ← 102

### Example 2 — Cache performance

A CPU runs at 3 GHz. RAM has a latency of 100 ns. L1 cache has a latency of 1 ns.

- Accessing RAM: 100 ns × 3 × 10⁹ cycles/s = **300 cycles wasted**
- Accessing L1 cache: 1 ns = ~**3 cycles**

→ Cache dramatically reduces the number of clock cycles wasted waiting for data.

## Common mistakes

- ❌ **Mistake:** Saying the PC holds the address of the *current* instruction.  
  ✅ **Correction:** The PC holds the address of the **next** instruction to be fetched.

- ❌ **Mistake:** Confusing MAR and MDR.  
  ✅ **Correction:** MAR = **address**; MDR = **data/instruction** at that address.

- ❌ **Mistake:** Saying more cores always means faster single-program execution.  
  ✅ **Correction:** More cores help with **parallelism** (running multiple tasks simultaneously); a single-threaded program may not benefit unless designed for multi-core.

- ❌ **Mistake:** Thinking pipelining makes individual instructions faster.  
  ✅ **Correction:** Pipelining increases **throughput** (more instructions per second overall), not the speed of any single instruction.

## Quick-check questions

1. What does PC stand for and what does it store?
2. What is the difference between the MAR and the MDR?
3. List the three stages of the fetch-decode-execute cycle.
4. Name three factors that can affect processor performance.
5. What is pipelining and why can branch instructions cause problems for it?
6. What happens to the PC immediately after an instruction is fetched?
7. What is an ISR?

<details>
<summary>Outline answers</summary>

1. Program Counter — the memory address of the **next** instruction to be fetched.
2. MAR holds a memory **address**; MDR holds the **data or instruction** at that address.
3. Fetch → Decode → Execute.
4. Any three of: clock speed, number of cores, cache size/levels, word length.
5. Pipelining overlaps instruction stages so multiple instructions are in progress simultaneously. Branch instructions can invalidate the pre-fetched instructions, causing a flush (wasted cycles).
6. It is incremented by 1 (so it points to the next instruction in sequence).
7. Interrupt Service Routine — the program that runs when a CPU interrupt occurs.

</details>
