## What you need to know

Before you can understand data structures, you need a solid grasp of the **primitive data types** — the fundamental building blocks that all programs use. This topic also covers **number systems** (binary, hexadecimal, denary), number representation (two's complement, floating point), and character encoding. Expect calculation questions.

## Key terms

| Term | Definition |
|------|-----------|
| **Integer** | A whole number (positive, negative, or zero); no decimal part |
| **Real / Float** | A number with a fractional/decimal part |
| **Boolean** | A data type with only two values: True or False |
| **Character** | A single letter, digit, or symbol |
| **String** | A sequence of characters |
| **Binary** | Base-2 number system; uses digits 0 and 1 only |
| **Hexadecimal** | Base-16 number system; uses digits 0–9 and A–F |
| **Bit** | A single binary digit (0 or 1) |
| **Byte** | 8 bits |
| **Two's complement** | A method for representing signed integers in binary |
| **Overflow** | When the result of an arithmetic operation exceeds the range of the data type |
| **Floating-point** | A binary representation of real numbers using a mantissa and exponent |
| **ASCII** | American Standard Code for Information Interchange — 7-bit character encoding (128 characters) |
| **Unicode** | A universal character encoding standard supporting over 1 million characters |

## Core notes

### Primitive data types

| Type | Description | Example value |
|------|------------|--------------|
| **Integer** | Whole numbers | 42, -7, 0 |
| **Real/Float** | Numbers with a decimal point | 3.14, -0.5 |
| **Boolean** | True or False | True |
| **Character** | A single character | 'A', '7', '!' |
| **String** | Sequence of characters | "Hello" |

### Number bases

| Base | Name | Digits used | Example |
|------|------|------------|---------|
| 2 | Binary | 0, 1 | 1011 |
| 10 | Denary (decimal) | 0–9 | 11 |
| 16 | Hexadecimal | 0–9, A–F | B |

Hex is used as a shorthand for binary: 1 hex digit = 4 bits.

**Conversions:**

Binary → Denary: use place values  
`1011₂` = 8+0+2+1 = **11₁₀**

Denary → Binary: divide by 2, record remainders  
11 ÷ 2 = 5 r1 → 5 ÷ 2 = 2 r1 → 2 ÷ 2 = 1 r0 → 1 ÷ 2 = 0 r1 → read up: **1011**

Binary → Hex: group into nibbles (4 bits)  
`10111100₂` → `1011 1100` → B C → **BC₁₆**

### Binary addition

```
  0111 (7)
+ 0101 (5)
------
  1100 (12)
```

**Overflow:** occurs when the result needs more bits than available.

### Two's complement

Used to represent **negative** numbers in binary.

**For an 8-bit system:**
- Positive numbers: 0 to 127 (MSB = 0)
- Negative numbers: -128 to -1 (MSB = 1)

**To find two's complement of a number:**
1. Write the positive number in binary
2. Invert all bits (flip 0s and 1s)
3. Add 1

Example: -6 in 8-bit two's complement  
+6 = 00000110  
Invert: 11111001  
Add 1: **11111010**

**Range for n bits:** -2^(n-1) to 2^(n-1) - 1  
For 8 bits: -128 to +127

### Floating-point representation

Real numbers are stored as: `value = mantissa × 2^exponent`

- **Mantissa** stores the significant digits (precision)
- **Exponent** stores the scale (range)
- More bits for mantissa → more precision
- More bits for exponent → larger range
- **Trade-off:** fixed total bits means more precision = less range, and vice versa

### Character encoding

**ASCII:**
- 7-bit encoding → 128 characters (0–127)
- Covers English letters, digits, basic punctuation, control characters
- 'A' = 65, 'a' = 97, '0' = 48

**Unicode:**
- Covers all scripts worldwide (over 1 million code points)
- **UTF-8:** Variable length (1–4 bytes); backwards compatible with ASCII
- **UTF-32:** Fixed 4 bytes per character; simple but wastes space for English text

## Worked examples

### Example 1 — Convert 43₁₀ to binary

43 ÷ 2 = 21 r **1**  
21 ÷ 2 = 10 r **1**  
10 ÷ 2 = 5 r **0**  
5 ÷ 2 = 2 r **1**  
2 ÷ 2 = 1 r **0**  
1 ÷ 2 = 0 r **1**  

Read remainders bottom to top: **101011**

### Example 2 — Two's complement addition

Calculate -6 + 9 in 8-bit two's complement:

-6 = 11111010  
+9 = 00001001  
Sum: 00000011 = 3 ✓

### Example 3 — Hex to binary

`3F₁₆`:  
3 = 0011, F = 1111 → **00111111₂**

## Common mistakes

- ❌ **Mistake:** Treating all negative two's complement numbers as just "normal binary with a 1 at the front."  
  ✅ **Correction:** The MSB in two's complement has a value of **-2^(n-1)**, not just a sign indicator. The rest of the bits are added to this.

- ❌ **Mistake:** Forgetting to add 1 when finding two's complement.  
  ✅ **Correction:** Two's complement = invert all bits **then** add 1. Forgetting to add 1 gives one's complement.

- ❌ **Mistake:** Saying more bits for the mantissa always makes floating-point numbers more accurate.  
  ✅ **Correction:** More mantissa bits increase **precision**; more exponent bits increase **range**. There is a trade-off.

## Quick-check questions

1. Convert 25₁₀ to binary.
2. Convert 10110100₂ to denary.
3. What is -12 in 8-bit two's complement?
4. Convert A7₁₆ to binary.
5. What is ASCII and why is Unicode necessary?
6. What is the range of values representable in 8-bit two's complement?

<details>
<summary>Outline answers</summary>

1. 11001₂ (16+8+1 = 25).
2. 128+32+16+4 = 180.
3. +12 = 00001100; invert = 11110011; add 1 = 11110100.
4. A = 1010, 7 = 0111 → 10100111₂.
5. ASCII is a 7-bit encoding for 128 characters (mainly English). Unicode is needed to represent characters from all the world's writing systems (over 1 million code points).
6. -128 to +127.

</details>
