# 1.3.2 Databases

> **Component:** 01 — Computer Systems | **Section:** 1.3 | **Sub-section:** 1.3.2

## What you need to know

Databases are organised collections of structured data. This topic focuses on **relational databases** — the dominant model for storing and querying structured data — along with the concepts and query language (SQL) that underpin them. You must also understand **entity-relationship modelling** and **normalisation**.

## Key terms

| Term | Definition |
|------|-----------|
| **Database** | An organised collection of structured data |
| **Table (relation)** | A structured set of data in rows and columns |
| **Field (attribute)** | A column in a table, representing a single characteristic |
| **Record (tuple)** | A row in a table, representing one entry |
| **Primary key** | A unique identifier for each record in a table |
| **Foreign key** | A field in one table that is the primary key in another, linking the tables |
| **Relational database** | A database organised into related tables linked by keys |
| **Normalisation** | The process of organising a database to reduce redundancy |
| **SQL** | Structured Query Language — language for querying and managing relational databases |
| **DBMS** | Database Management System — software for creating, managing, and querying databases |
| **ACID** | Properties ensuring reliable transactions: Atomicity, Consistency, Isolation, Durability |

## Core notes

### Relational databases

Data is organised into **tables** (relations). Tables are linked via **keys**:
- **Primary key:** Uniquely identifies each record (e.g. StudentID)
- **Foreign key:** Appears in one table, references the primary key of another

**Example:**

| StudentID (PK) | Name | CourseID (FK) |
|---------------|------|--------------|
| 1 | Alice | C01 |
| 2 | Bob | C02 |

| CourseID (PK) | CourseName |
|--------------|-----------|
| C01 | Computer Science |
| C02 | Mathematics |

### ER diagrams

Show entities and their relationships:

- **One-to-one** (1:1) — e.g. one person has one passport
- **One-to-many** (1:M) — e.g. one course has many students
- **Many-to-many** (M:M) — e.g. students can take many courses and courses can have many students (resolved with a link table)

### Normalisation

Reduces data redundancy and improves data integrity.

| Form | Requirement |
|------|------------|
| **1NF** | No repeating groups; each cell contains a single value; each record is unique |
| **2NF** | In 1NF + no partial dependencies (non-key attributes depend on the whole primary key) |
| **3NF** | In 2NF + no transitive dependencies (non-key attributes depend only on the primary key) |

### SQL queries

```sql
-- Select all students on course C01
SELECT Name
FROM Student
WHERE CourseID = 'C01';

-- Join tables
SELECT Student.Name, Course.CourseName
FROM Student
INNER JOIN Course ON Student.CourseID = Course.CourseID;

-- Insert a record
INSERT INTO Student (StudentID, Name, CourseID)
VALUES (3, 'Carol', 'C01');

-- Update a record
UPDATE Student
SET CourseID = 'C02'
WHERE StudentID = 1;

-- Delete a record
DELETE FROM Student
WHERE StudentID = 3;
```

### ACID properties

| Property | Meaning |
|----------|---------|
| **Atomicity** | A transaction is all-or-nothing; if any part fails, the whole transaction is rolled back |
| **Consistency** | A transaction brings the database from one valid state to another |
| **Isolation** | Concurrent transactions do not interfere with each other |
| **Durability** | Once committed, a transaction is permanent — even if the system fails |

## Worked examples

### Example — SQL with JOIN

**Task:** Find the names of students and the names of their courses.

```sql
SELECT Student.Name, Course.CourseName
FROM Student
INNER JOIN Course ON Student.CourseID = Course.CourseID
ORDER BY Student.Name;
```

## Common mistakes

- ❌ **Mistake:** Confusing primary key and foreign key.  
  ✅ **Correction:** Primary key uniquely identifies records *in its own table*; foreign key references the primary key *of another table*.

- ❌ **Mistake:** Writing `WHERE` conditions without quotes for text values.  
  ✅ **Correction:** String values in SQL need quotes: `WHERE Name = 'Alice'` not `WHERE Name = Alice`.

## Quick-check questions

1. What is a primary key?
2. What is a foreign key and how does it relate tables?
3. Write a SQL query to select all records from a table called `Product` where the price is greater than 10.
4. What does ACID stand for?
5. What does 1NF require?

<details>
<summary>Outline answers</summary>

1. A field (or combination of fields) that uniquely identifies each record in a table.
2. A foreign key is a field in one table that references the primary key of another table, linking related data.
3. `SELECT * FROM Product WHERE Price > 10;`
4. Atomicity, Consistency, Isolation, Durability.
5. No repeating groups; each cell contains one value; each record is unique (has a unique identifier).

</details>
