## What you need to know

Networking is a substantial topic. You need to understand the difference between types of networks, how data is transmitted, the protocols that make communication possible, and the hardware involved. This topic links strongly to security (1.3.1) and web technologies (1.3.4). Expect description, explanation, and comparison questions in the exam.

## Key terms

| Term | Definition |
|------|-----------|
| **LAN** | Local Area Network — a network within a small geographical area (e.g. a building) |
| **WAN** | Wide Area Network — a network spanning large geographical areas, often connecting LANs |
| **Internet** | A global network of interconnected networks using TCP/IP protocols |
| **Protocol** | An agreed set of rules that govern how data is transmitted between devices |
| **IP address** | A unique numerical label assigned to each device on a network |
| **IPv4** | 32-bit IP address format, written as four decimal octets (e.g. 192.168.1.1) |
| **IPv6** | 128-bit IP address format, written in hexadecimal; provides far more unique addresses |
| **Packet** | A unit of data sent across a network; includes a header (source/destination/sequence) and payload |
| **Router** | A device that forwards packets between networks, determining the best route |
| **Switch** | A device that connects devices within a LAN and forwards frames using MAC addresses |
| **DNS** | Domain Name System — translates human-readable domain names (e.g. bbc.co.uk) to IP addresses |
| **HTTP** | HyperText Transfer Protocol — used to transfer web pages (unencrypted) |
| **HTTPS** | HTTP Secure — HTTP with SSL/TLS encryption |
| **TCP** | Transmission Control Protocol — reliable, connection-oriented protocol; guarantees delivery and order |
| **UDP** | User Datagram Protocol — faster but unreliable; no guarantee of delivery or order |
| **Subnet mask** | Defines which part of an IP address is the network address and which is the host address |
| **MAC address** | A unique hardware identifier assigned to a network interface card (NIC) |
| **Firewall** | Hardware or software that monitors and filters network traffic based on rules |
| **Topology** | The arrangement (physical or logical) of devices in a network |

## Core notes

### Types of network

| Feature | LAN | WAN |
|---------|-----|-----|
| **Geographical scope** | Small (e.g. school, office) | Large (cities, countries, global) |
| **Ownership** | Usually owned by one organisation | Often uses leased lines from telecoms |
| **Speed** | High — typically 100 Mbps to 10 Gbps | Variable; often slower due to distance |
| **Cost to set up** | Relatively low | High |
| **Example** | School network | Internet; bank branch connections |

### Network topologies

**Star topology:**
- All devices connect to a central **switch** or hub
- Failure of one device does not affect others
- Failure of the central switch brings down the whole network
- Easy to add new devices; easy to monitor traffic
- Most common in modern LANs

**Bus topology:**
- All devices share a single cable (the bus)
- Simple and cheap to set up
- A break anywhere in the cable brings down the whole network
- Data collisions occur when two devices transmit simultaneously
- Now rarely used in practice; mainly a historical/exam topic

**Mesh topology:**
- Every device connects to every other device (full mesh) or at least multiple paths exist (partial mesh)
- Highly fault-tolerant — multiple routes if one link fails
- Very expensive — large number of connections required
- Used in WANs and critical infrastructure

> **Physical vs logical topology:** Physical = how cables are actually laid out. Logical = how data flows through the network. (A network can have a physical star but a logical bus.)

### Transmission media

**Copper cable (twisted pair):**
- Used for Ethernet (Cat5e, Cat6 cables)
- Cheaper than fibre
- Susceptible to electromagnetic interference (EMI)
- Shorter maximum distance before signal degrades

**Fibre optic:**
- Uses light pulses instead of electrical signals
- Much higher bandwidth and longer distances
- Not susceptible to EMI
- More expensive and harder to install/repair

**Wi-Fi (wireless):**
- Uses radio waves (2.4 GHz or 5 GHz bands)
- Convenient; no physical cables needed
- Susceptible to interference; less secure unless encrypted
- Range limited by walls, distance, and interference

### The TCP/IP model (four layers)

| Layer | Name | Role | Example protocols |
|-------|------|------|-------------------|
| 4 | **Application** | Provides network services to applications | HTTP, HTTPS, FTP, SMTP, DNS, SSH |
| 3 | **Transport** | Breaks data into segments; manages end-to-end delivery | TCP, UDP |
| 2 | **Internet** | Addressing and routing of packets across networks | IP |
| 1 | **Link** (Network Access) | Physical transmission of data on local network | Ethernet, Wi-Fi |

**How it works — encapsulation:**
- At each layer going down, a header (and sometimes trailer) is added.
- At the receiving end, each layer strips its header and passes the data up.

### TCP vs UDP

| Feature | TCP | UDP |
|---------|-----|-----|
| **Reliability** | Guaranteed delivery; resends lost packets | No guarantee; no resending |
| **Order** | Data arrives in correct order | Packets may arrive out of order |
| **Speed** | Slower (overhead of acknowledgements) | Faster |
| **Use case** | Web pages, email, file transfer | Video streaming, gaming, DNS lookups, VoIP |

### IP addressing

**IPv4:** 32-bit address → ~4.3 billion unique addresses (nearly exhausted)  
Format: four 8-bit octets in decimal, e.g. `192.168.0.1`

**IPv6:** 128-bit address → ~3.4 × 10³⁸ unique addresses  
Format: eight groups of four hex digits, e.g. `2001:0db8:85a3:0000:0000:8a2e:0370:7334`

**Private vs public:**
- **Private:** Used inside a LAN (e.g. 192.168.x.x); not routable on the internet
- **Public:** Globally unique; assigned by ISPs

**Subnet mask:** Tells a device which part of an IP address is the network (same for all devices on that network) and which part is the host.

### Client-server vs peer-to-peer

| Feature | Client-server | Peer-to-peer |
|---------|--------------|--------------|
| **Central server** | Yes | No |
| **Resource management** | Centralised | Distributed among peers |
| **Security** | Easier to control centrally | Harder to secure |
| **Scalability** | Good — server upgraded independently | Degrades as more peers join |
| **Typical use** | Web services, email, corporate networks | File sharing, Bitcoin, small home networks |
| **Cost** | Higher (dedicated server hardware) | Lower (no dedicated server needed) |

### Network hardware

| Device | Purpose |
|--------|---------|
| **NIC** | Network Interface Card — provides the hardware connection to the network |
| **Hub** | Broadcasts all received data to all ports (dumb; largely obsolete) |
| **Switch** | Forwards frames only to the correct port using MAC address table |
| **Router** | Routes packets between networks using IP addresses; connects LAN to internet |
| **WAP** | Wireless Access Point — provides Wi-Fi connectivity |
| **Firewall** | Monitors and filters traffic; blocks unauthorised access |

### Wi-Fi security

- **SSID** — Service Set Identifier; the name of a Wi-Fi network
- **WPA2/WPA3** — encryption protocols for Wi-Fi (use AES encryption)
- **MAC address filtering** — only devices with listed MAC addresses can connect
- **Hiding SSID** — network name not broadcast; provides minimal extra security

## Worked examples

### Example 1 — Packet transmission using TCP/IP

A user requests a web page from a server:

1. **Application layer:** Browser sends HTTP GET request
2. **Transport layer:** TCP splits request into segments; assigns port numbers (port 80 for HTTP)
3. **Internet layer:** IP adds source and destination IP addresses; creates packets
4. **Link layer:** Packets converted to frames with MAC addresses; sent physically

At the server, each layer strips its header in reverse order.

---

### Example 2 — IPv4 subnetting (simple)

IP address: `192.168.1.45`  
Subnet mask: `255.255.255.0`

- Network part: `192.168.1` (first 24 bits)
- Host part: `.45` (last 8 bits)
- This subnet can hold 254 hosts (addresses .1 to .254; .0 is network address, .255 is broadcast)

## Common mistakes

- ❌ **Mistake:** Saying a router connects devices within a LAN.  
  ✅ **Correction:** A **switch** connects devices within a LAN. A **router** connects *different* networks together.

- ❌ **Mistake:** Confusing TCP and UDP by saying TCP is always better.  
  ✅ **Correction:** UDP is preferable when **speed matters more than reliability** — e.g. live video streaming where a dropped frame is better than a delayed one.

- ❌ **Mistake:** Saying IPv6 addresses are just longer IPv4 addresses.  
  ✅ **Correction:** IPv6 uses a completely different format (128-bit hexadecimal); it also has built-in features not present in IPv4.

- ❌ **Mistake:** Treating a hub and a switch as the same thing.  
  ✅ **Correction:** A hub broadcasts to all ports; a switch sends only to the correct port using MAC address tables — switches are much more efficient.

1. What is the difference between a LAN and a WAN?
2. Name three network topologies and give one advantage of each.
3. What does DNS do?
4. Why was IPv6 introduced?
5. Give two differences between TCP and UDP.
6. What is the role of a router?
7. Name two protocols used at the Application layer of the TCP/IP model.

<details>
<summary>Outline answers</summary>

1. LAN — small geographical area; WAN — large geographical area / connects multiple LANs.
2. Star: failure of one device does not affect others. Bus: cheap and simple to set up. Mesh: highly fault-tolerant (multiple paths).
3. DNS translates domain names (e.g. bbc.co.uk) into IP addresses.
4. IPv4 addresses were running out (~4.3 billion max); IPv6 provides vastly more unique addresses.
5. TCP: reliable / guaranteed delivery / ordered / slower. UDP: no guarantee / no ordering / faster.
6. A router routes packets between different networks, determining the best path using IP addresses.
7. Any two of: HTTP, HTTPS, FTP, SMTP, IMAP, DNS, SSH.
